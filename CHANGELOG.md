# D8W3CSS changelog

## Next release

- Upgrade path: the 5 JavaScript behaviors released in 2.0.x (`d8w3cssTheme`, `d8w3cssMainNav`, `d8w3cssMenuDepth`, `d8w3cssResponsiveMenu`, `d8w3cssFullOpacity`) keep working as deprecated aliases of their 3.0 names, and the migrate-classes script rewrites them.
- Upgrade path: the Font Awesome 4, 5 and 6 library ids are deprecated aliases of Font Awesome 7 (local or CDN).
- Upgrade path: the rename map lists every 2.0.18 stylesheet that moved (the 53 color scheme files, the font files and Font Awesome 4), so the migrate-classes report gives each old path its new file; `clickable-dropdown-menu-fa-right` and `-fa-right-h` map to `w3css-menu__right-arrow`.
- Footer menu: link and button padding is back (the rule had lost its `.w3css-menu__list--menu-footer` selectors).
- composer.json declares a conflict with amun, amunet and anhur older than 3.0 and W3CSS Paragraphs older than 2.0, so Composer updates them together with the theme.
- README: the upgrade notes now say plainly that old class names are no longer printed (run migrate-classes on a sub-theme), which stored classes the script rewrites and which it does not, that the settings form keys changed, and what was removed.

- Settings update: a stored color scheme of `'0'` or empty (saved before 2.0) is read as `none`, so the update no longer warns that `current_theme` conflicts with the new key.
- Predefined color schemes: a scheme no longer loses earlier colors of the same layer (transparent headers, menus and footers, white `.w3-theme`, black body text). The shared paint rules fell back to `revert-layer` for a token a scheme leaves out, and `revert-layer` rolls back the whole layer for that property. Each custom scheme file now carries only the paint rules for the tokens it sets, as `var(--token)` with no fallback, in the same layers and order (and the copyright text and footer box hover shadow of the palette schemes); `w3css-scheme-custom-paint.css` and its library stay, empty. The rules come from `scripts/scheme-paint-rules.json`; `scripts/build-scheme-paint.py` writes them, and `--check` fails on drift or on any `revert-layer` fallback in `css/predefined/`. A sub-theme that sets a `--w3css-custom-*` token its scheme does not set gets no rule for it any more.
- Accessibility (WCAG 2.2 AA): the `w3-text-<color>` and `w3-hover-text-<color>` classes use readable text versions of the palette (`--w3-text-<color>`, 4.5:1 on white and light gray, same hue); the background classes keep the original W3.CSS colors.
- Accessibility: predefined schemes Lime Grass, Slate Amber, Harbor Blue, Harbor Steel, Midnight Ember, Orchid Purple, Deep Cyan, Teal Coral and Forest Green have darker heading colors; Ocean Blue, Deep Cyan, Teal Coral, Forest Green and Indigo Lagoon have slightly darker headers so their white links and text reach 4.5:1.
- Accessibility: Windows high contrast mode shows the required and error form icons and animated gradient titles; a styled skip link (`css/components/w3css-skip-link.css`) appears on keyboard focus.
- Main menu: the hover text color and the submenu arrow follow the scheme's hover colors again (light ground, dark text).
- Breakpoints use rem, as Solo does: up to 37.49875rem / from 37.5rem (was 600px / 601px) and up to 61.99875rem / from 62rem (was 992px / 993px), so no gap or overlap, and they follow the browser text size; the screen-size script uses the same queries. Sub-themes and W3CSS Paragraphs follow.
- W3.CSS library and reset (`css/base/w3css-drupal.css`, `css/base/w3css-base.css`): rebuilt for current browsers (Baseline widely available plus the current and previous Chrome, Edge, Firefox, Safari and iOS Safari): the reset drops Internet Explorer and old Edge rules and uses unprefixed `appearance`, `::file-selector-button`, inherited box-sizing (now declared once) and `max-width: 100%` on images, video, canvas and svg; modal, overlay and `.w3-top`/`.w3-bottom` use `inset`; the slide, zoom and spin animations use `translate`, `scale` and `rotate`, so they no longer undo `.w3-display-middle` centering; headings use `text-wrap: balance`; 17 new classes (`w3-stack`, `w3-cluster`, `w3-flex-column`, `w3-items-center`, `w3-justify-center`, `w3-justify-between`, `w3-gap-small`, `w3-gap-large`, `w3-place-center`, `w3-ratio-square`, `w3-ratio-photo`, `w3-ratio-video`, `w3-cover`, `w3-screen-height`, `w3-truncate`, `w3-query-container`, `w3-snap-row`) and a `--w3-grid-min` setting for `w3-grid-auto`. Every existing class keeps its name; visible changes are listed in `css/w3-css/SOURCE.md`.
- Rename list and migration script: `docs/CLASS-MIGRATION.md` and `docs/class-migration.html` now list every 3.0 rename by kind (classes, ids, CSS variables, JavaScript behaviors, once ids, data attributes, library ids, files), generated by `scripts/class-list.py` from `ClassMap.php` and `src/Upgrade/w3css-rename-map.json`; `scripts/migrate-classes.php` also rewrites CSS variables, JavaScript names and data attributes, reports library ids and moved file paths, and rewrites library ids in `*.info.yml` and `*.libraries.yml` with `--apply --yml`; the `class-list` CI job fails on drift.
- Class and JavaScript names: theme classes follow their template (`w3css-page__*` for page region boxes, inner wrappers `w3css-<region>__inner`; ids keep their names, `w3css-form-element__*`, `w3css-status-messages__*`, `w3css-status-report__*`, `w3css-views-view__*`, `w3css-node-edit-form__*`, `w3css-settings-nav__*`, `w3css-scheme-picker__*` and more); behaviors `w3cssTheme` (now `w3cssPage` plus `w3cssSearch`), `w3cssMainNav`, `w3cssResponsiveMenu`, `w3cssFullOpacity`, `d8w3cssSettingsSearch` are renamed, as are their `once()` ids, the settings form `data-w3css-*` attributes, the `--w3css-theme-*` variables (now `--w3css-scheme-*`), `--d8s-*` (now `--w3css-settings-*`) and the three menu variables. The 2.x class migration points straight at the new names. Names used by amun, amunet and anhur are unchanged. Old to new: README, Upgrade notes: class, id, behavior and variable names.
- Library ids: every asset library has a new id (`scheme-<name>`, `font-<name>-google` and `font-<name>-local`, `component-...`, `layout-...`, `utility-fade`, `admin-settings-form`, `font-awesome-7-local` and `-cdn`; the starter sub-theme library is `subtheme-global`). The old ids stay as deprecated aliases and are removed in 4.0.0; `w3-css` and `d8w3css-global-styling` are now one library per CSS file (see the CSS and JS file paths entry below) and stay as deprecated aliases that load all the parts. A sub-theme with `libraries-override` on an old id must switch to the new id, because an alias has no files to override (README, Upgrade notes: library ids). All libraries now come from `libraries/w3css-libraries.json`; `scripts/build-libraries.py` writes the libraries file and `src/SchemeLibraries.php`, and `--check` fails on drift. Stored scheme settings are unchanged; stored font settings change (next entry).
- Predefined color schemes: the 22 files of `css/w3-css-theme/` and the 31 of `css/w3-css-theme-custom/` are now one folder, `css/predefined/`, named `w3css-<scheme name>.css` (for example `w3css-royal-blue.css`, `w3css-harbor-steel.css`). Library ids, stored scheme values and class names are unchanged, so sites keep their scheme; a sub-theme that copied a scheme file by its old path must use the new name.
- W3.CSS library: `w3-modern.css` is now `w3css-drupal.css`, every rule in a `w3css.*` cascade layer, every color a token (`--w3-*`, with `--w3-<color>-on` for text), color classes assign `--r-*` region variables, and `!important` remains only for show/hide, the focus ring, reduced motion and three inline-style overrides; site CSS that relied on beating a W3 class's `!important` may now win or lose differently.
- Extended classes and the 11 color libraries (`css/utilities/w3css-extended-classes.css`, `css/utilities/w3css-color-<name>.css`): in `w3css.*` layers, every color a token (`--w3-<class>` and `--w3-<class>-on`, `--w3-ext-*` for the extended classes), all `!important` removed; the link, button and hover classes now lose to site CSS that is not in a layer instead of beating it.
- The 22 predefined color schemes (now `css/predefined/w3css-<name>.css`, `w3css-scheme-palette.css`, `w3css-scheme-keyframes.css`): scheme files are tokens only in `w3css.schemes`, and the abbreviated `--w-*` names are now `--w3css-theme-*` (for example `--w-l5` and `--w-l5-b` are `--w3css-theme-l5-text` and `--w3css-theme-l5-background`); the `.w3-theme*` classes assign `--r-*` region variables and all their `!important` is gone, so site CSS that is not in a layer now wins over them; a sub-theme or custom scheme that read or set the old names must use the new ones. Stored scheme settings and `w3-theme-*` class names are unchanged.
- Component CSS (`css/components/*`, 30 files): every rule in `@layer w3css.theme`, every color a token (`--w3-*` palette or a file-local `--w3css-<component>-<property>` in `w3css.tokens`), `!important` removed where nothing needs it; the rules that beat core, contrib, Paragraphs Bundles or VVJ CSS today (1057 declaration and selector pairs) moved unchanged, with their `!important` where still needed, to the unlayered `css/base/w3css-host-overrides.css`; bare element selectors start from `:where(.w3css-page-wrapper, #w3css-main-nav-vertical)`, so they no longer reach elements outside the page wrapper and the vertical menu.
- The 30 custom color schemes and the custom palette (now in `css/predefined/`, `w3css-scheme-custom.css`, new `w3css-scheme-custom-paint.css`): scheme files are tokens only in `w3css.schemes`, the abbreviated `--w-*` names are now `--w3css-custom-*` (and `--w-kbtn`, `--w-kbd` are `--w3css-theme-keyframe-button` and `-keyframe-border`, shared with the predefined schemes), every rule that read them moved into the shared files in `w3css.*` layers, and all their `!important` is gone, so site CSS that is not in a layer now wins over them; 00000 and 00001 use the shared keyframes instead of their own copies. Stored scheme settings and `w3-theme-*` class names are unchanged.
- Base and page layout CSS (`css/base/w3css-base.css`, `css/layout/*`): in `w3css.reset`, `w3css.base` and `w3css.layout` layers; the declarations that beat core, contrib, Paragraphs Bundles or VVJ CSS before layering moved unchanged to the unlayered `css/base/w3css-host-overrides.css` (bare element selectors now start with a zero-specificity `:where()` of the page wrapper and vertical menu), and `!important` stays only there, where it still beats a module rule.
- Breakpoint files (`css/theme/*`) and the 177 font stylesheets: in `w3css.theme` and `w3css.base` layers, rgb shadows are tokens, `!important` stays only where it still beats a module rule; the declarations that beat core, contrib or Paragraphs Bundles CSS moved unchanged to `css/base/w3css-host-overrides.css` (theme files) or to an unlayered tail of the font file (heading fonts and sizes, behind a `:where()` page-wrapper root). `html` and `body` stay in the base layer, so a heading-only font from a font file now loses its body font to Paragraphs Bundles `w3-modern.css` when that module is installed.
- Stored font choices: the font settings hold `w3css-font-<name>` instead of `d8w3css-<name>`. A post update (`rename_typography_font_values`) rewrites the site font, heading font and special font in this theme and every installed sub-theme; a value not yet rewritten still loads its font.
- CSS and JS file paths: every CSS and JS file has a `w3css-` name in a folder that says what it is (`css/base/`, `layout/`, `components/`, `utilities/`, `predefined/`, `admin/`, `js/admin/`, `js/utilities/`); the font files are `fonts/w3css-font-<name>-local.css` (the copy in `fonts/fonts-files/`) and `fonts/w3css-font-<name>-google.css` (the Google import), `fonts/w3css-font-awesome-7.css`; `default-node.css` and `teaser-mode.css` are one `w3css-node.css`, `global-menu.css` and `user-menu.css` one `w3css-menu.css`, `w3-css-theme-shared-custom.css` and `-custom-b.css` one `w3css-scheme-custom.css`. `w3-css` and `d8w3css-global-styling` are split into one library per file (ids `base-...`, `layout-...`, `component-...`, `utility-...`, `theme-...`); the two old ids stay as deprecated aliases that depend on every part, so a sub-theme that attaches them keeps working, and `info.yml` lists the parts. A sub-theme that overrides or copies a file by its old path must use the new path (list: README, Upgrade notes: library ids). Rule content is unchanged. Still to come: the breakpoint files, `forms.css`, `system-admin.css`, `layout-builder.css` and `js/custom.js` are cut into component files, and `components/user-login.css` and `node-form.css` merge into their layout files.
- Social links: built as inline SVG in the link's colour, so they follow the link color and hover. The Font Awesome class hooks, their JavaScript and the old social icon images are gone; a sub-theme that styled `.w3css-social-media a > i` or `.w3-social-icon` should use `.w3css-social-media__icon`.
- Font Awesome: the only choices are now Font Awesome 7 locally or from the CDN. Sites on the 5.x or 6.x CDN option move to Font Awesome 7 from the CDN. Icons that exist only under Font Awesome 4 names may need renaming.
- Templates: brought in line with Drupal 11 core (no redundant landmark roles, description ids on details, the description-before position in form elements, `view_mode` for titles, no `spaceless`).
- Sidebar menus: a menu placed in the left or right sidebar opens its submenus on hover or with the arrow, in the page flow below their parent, with the arrow beside its link; before, the submenu flew out over the items below it with no background of its own.
- Contextual links (the pencil menu) show one link per row again, as in Drupal core; the theme's floated link items had put two on one row in a narrow column.
- Icons: the interface icons (menu arrows, hamburger and close buttons, required asterisk, form error, Layout Builder plus, admin list chevron) are now Google Material Symbols (Outlined, weight 400), trimmed to their drawing, and take the text color through `currentColor` or a CSS mask. The theme no longer uses `arrow-right-ccc.svg` and `search-ccc.svg`; both files stay so sub-themes that reference them keep working. Brand logos for the social links keep their own drawings.
- Header search: the open form is one field with a joined submit button, both 44px high, built with flexbox and the theme's own border classes; the floated 70/30 layout, the magnifier image and the off-screen text on the button are removed. The button shows its "Search" label.
- Extend and Appearance pages: every module and theme description is a short, professional statement that begins with a verb; credits, links and version notes moved out of the info files.
- New W3CSS Theme logo: it is the theme's default logo (replace or turn it off in Appearance settings), and it sits at the top of the settings menu, which scrolls under it.

- Text follows the drupal.org standards: the theme description begins with a verb and its demo link no longer opens a new window, settings titles are in sentence case without "Check this box to", "YouTube" and "LinkedIn" are spelled as the brands spell them, the credit setting no longer says "Please", and the README follows the drupal.org README template (sections, headings, lists, links and code).
- Every color theme has a new name of two or three words (00008 - Red Turquoise is now Indigo Lagoon, Amber is now Golden Amber). Only the name shown on the settings page changed: the stored value and the w3-theme-* classes are the same, so every site keeps its color theme. The old to new list is in README.md.
- Accessibility: the animated site name, text and page title gradients sweep once in 5 seconds instead of looping forever; the copyright and credit lines are no longer faded to 60%; the search form is a search landmark and its button shows its text in forced colors; submenu arrows are named after their link; menu links that open a new tab say so to screen readers; the current pager page has aria-current and its active style (a missing space dropped it); the header or sticky menu no longer covers a focused element; focused or #fragment content is never left faded; the linked-image hover zoom honors reduced motion.
- Class migration `--content`: paragraphs and Layout Builder inline blocks are now rewritten in place on the revision their page shows (a new revision was never shown), and links to an old id on another page or site are listed for review instead of being renamed.
- Social link settings accept only https://, http:// or site-path addresses and unsafe stored links are stripped on output; "None" fonts and the maintenance page no longer attach libraries that do not exist.
- The default RSS social link is `/rss.xml` (was `rss.xml`, which pointed at `/node/rss.xml` on sub-pages). Existing sites keep their saved value.
- Comment ages ("3 min ago") and the copyright %year% no longer stay frozen in cached pages; "Default" and "None" width and animation choices no longer print a stray `none` class; the search button is named "Search" for screen readers; node form status details stay hidden from users core hides them from.
- Settings form: region color fields accept only CSS class names; font and animation links are descriptive and open safely; reduced motion stops the looping text and border animations; dead details keys and the script that closed every settings section are removed; the starter sub-theme info is cleaned; composer.json drops the packages.drupal.org repository.
- Templates: menu link classes are no longer glued together; #anchor, mailto: and tel: menu items are real links and new-window links get rel="noopener"; menu blocks are navigation landmarks named by their label; maintenance pages always show their messages and content with the header outside main; field labels are no longer `<label>` elements without a control; scrollable tables can be reached by keyboard; typos fixed in form error markup.
- Styles: every link, button and form field shows a keyboard focus ring (the base theme had removed it); the side menu and its submenus stay visible when JavaScript is off or fails; base and menu text sizes follow the visitor's browser text size; menu floats and form margins flip for right-to-left languages; leftover commented FontAwesome code and dead selectors are removed.
- Style: stylesheets in css/ pass core Stylelint (property order, `::before`/`::after` notation, lowercase keywords, Prettier layout) with no change to computed values; the vendored W3.CSS files and the generated color palettes are excluded from linting and unchanged.
- Settings: the social icon size styles load only when the social icons are shown; the animated-border boxes animate only their shadow, so reveal on scroll fades them at its own speed; the equal-columns and special-font settings say what they do with one sidebar and with local fonts.
